Which clipboard payload survives a paste into X?

X’s web composer collapses pasted newlines into spaces. That breaks Threader’s copy step: the numbering separator is a blank line, so 1/12 lands inline, and any paragraph inside a post arrives as one slab. This page writes the same text to the clipboard eight different ways so you can find out which one, if any, X keeps.

Serving it

Opening this from file:// makes the async Clipboard API fail with “Write permission denied” — the origin is opaque, so the browser refuses. The page falls back to the older copy-event API, which needs no permission and writes the same two flavours, so it should still work.

If a row still fails, serve it over localhost instead and reload:

python3 -m http.server 8000 --directory docs/experiments

Then open http://localhost:8000/clipboard-line-breaks.html. The status next to each button says which route it took, so note that alongside the result — a variant that only works via one route is worth knowing about.

How to run it

  1. Open this file in the browser you actually post from.
  2. Click Copy on a row.
  3. Paste into the local paste area at the bottom first — that shows what the clipboard really holds, independent of X.
  4. Then paste into X’s composer (don’t post it — just look).
  5. Record whether the blank line survived. Then try the next row.

The sample text is deliberately Threader-shaped: two paragraphs and a numbering suffix, which is exactly the structure that breaks.

What we learn

A works Nothing is wrong — the problem is elsewhere, or already fixed by X.
B, C, D or G works Ship that HTML flavour in apps/web/src/clipboard.ts. Threader already writes text/html; only toHtml() needs to change.
E works but B–D don’t X prefers text/plain when both are present, so we must omit it — which breaks pasting anywhere else. Needs a per-target choice.
F or H works It is a line-ending problem, not a format problem. Cheapest possible fix.
Nothing works Unfixable from our side. Fall back to the plan: set the profile’s numbering separator to a space, and have the wizard flag posts containing newlines so the retyping is guided rather than remembered.
